# Hosting the Ledger page

Live at **`penalty-ledger.pages.dev`** since 2026-09-27, on Cloudflare Pages,
**built from this repository**: the Pages project `penalty-ledger` is connected
to GitHub, production branch `main`, no build command, output directory
`docs/`. Every push to `main` redeploys it. The page carries no byline.

It was first a direct upload to `cms-penalty-ledger.pages.dev` (2026-09-19),
from a different Cloudflare account. That project still holds the name, so the
Git-built project took a new one. The old address serves a frozen copy until
that project is deleted.

**The page now follows a push by itself.** The weekly task pushes each new
capture, and the push rebuilds the page. The task still checks what the page
serves against `docs/data/meta.json` on every run, logs `LIVE PAGE BEHIND` when
they differ, and exits 3 so Task Scheduler shows it: a failed build would
otherwise look exactly like a successful week.

## Deploying an update

Push to `main`. The page's data is regenerated by `tools/cms_export.py`,
normally by the weekly task rather than by hand. A build takes under a minute;
the Cloudflare dashboard (Workers & Pages, `penalty-ledger`, Deployments)
shows each one and its log.

`docs/` is the deploy root as it stands: `index.html`, `ledger.js`, `data/` and
`facilities/`. Nothing next to `docs/` is published.

Line endings are pinned to LF by `.gitattributes`, and `cms_export.py` writes
its JSON with `newline="\n"`. Cloudflare builds from the repository, so it
publishes exactly what a clone holds.

## What to check after a deploy

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://penalty-ledger.pages.dev/
curl -s https://penalty-ledger.pages.dev/ | grep -ciEf "$LEAK_TERMS"   # a terms file kept outside this repository
```

Zero is the expected answer to the second.

**Then open it and read a real facility against `cms_ledger.py`.** A 200 says
nothing about whether the page agrees with the engine. Outcrop's page was live,
green and wrong about its headline field for an hour on 2026-09-19, and only
comparing it to the command line found it. The check that was run here:

```bash
python tools/cms_ledger.py --ccn 015133      # MAGNOLIA RIDGE, GARDENDALE AL
```

against the same facility on the page. Both gave one fine of $392,125, the same
two penalties CMS no longer publishes (2022-06-24 $11,915, last listed
2025-06-25; 2018-02-01 $9,168, last listed 2021-12-27) and the same three
inspection cycles. **Check the dropped-penalty block specifically**: it is the
thing no other consumer tool shows, so it is the thing worth proving still
renders.

## The weekly capture

Windows task *CMS nursing-home capture*, weekly, running
`tools/cms_scheduled.py` with **this repository** as the working directory. It
was repointed on 2026-09-19 when the engine moved; it previously ran from the
workstation root, and would have failed on its next run otherwise.

It captures, commits and pushes the capture, re-exports `docs/data` and
commits and pushes that: two commits against one repository, each taking only
its own path. The second push rebuilds the page.
